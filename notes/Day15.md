# Day15 · 掷骰子

> 一句话：**模型不会"决定"下一句说什么，它只是算出一张概率表，然后按表抽签——temperature 就是你调"抽签有多随性"的旋钮。**

---

## 一、接上昨天

昨天讲清了两件事：它按 token 读、它只能看见窗口里的东西。

但还留着最大的一个疑问没答：

> 它为什么有时候一样的问题答得一模一样，有时候又每次都不一样？

今天讲透这个，顺带说清它**是什么时候学会说话的**。

---

## 二、生活里的场景：它不是想，它是抽

想象一个只会做一件事的人：你给他半句话，他掏出一个小本子，上面写着「下一个字可能是哪些、各有多大机会」，然后用骰子挑一个。

- 掷出「好」→ 补上「好」
- 掷出「不」→ 补上「不」

补完一个字，把这个字接到句子后面，**再掷一次**。就这样一个字一个字往下掷，直到掷出「结束」。

模型就是这样工作的。它没有"想好了整句话再写"，它是**边说边掷**。

这个"小本子"就是概率表：

```
今天天气真___  ->  好 50%  不 22%  挺 13%  还 8%  凑 4%  糟 3%
```

不是"它觉得好"，是「好」在这张表里排第一。

---

## 三、temperature：骰子的"随性程度"

既然是掷骰子，就有一个旋钮能调：**temperature**，中文叫「温度」。

- **调到 0**：不掷了，永远拿概率最高的那个 → 每次都一样
- **调大**：把冷门选项的机会抬起来，骰子更野 → 每次都不一样，也更容易胡说

跑一遍看它怎么改这张表：

```powershell
cd C:\Users\22155\ai-agent-journey
.venv\Scripts\python.exe -X utf8 code\day15_sampling.py
```

演示一的输出（我本机实测）：

```
  T = 0
    好 100%
  T = 0.3
    好 93%   不 6%   挺 1%
  T = 0.7
    好 64%   不 20%   挺 9%   还 5%   凑 2%   糟 1%
  T = 1.5
    好 38%   不 22%   挺 16%   还 11%   凑 7%   糟 6%
```

看 T=0 和 T=1.5 的差别：

|       | 「好」  | 「糟」 |
| ----- | ---- | --- |
| T=0   | 100% | 0%  |
| T=1.5 | 38%  | 6%  |

T=0 时「糟」根本没机会；T=1.5 时它有一成机会冒出来。**温度不改模型会什么，只改它敢不敢说冷门的。**

再抽 20 次，看实际效果：

```
  T = 0    好x20
  T = 1.0  糟x1  好x12  还x1  挺x1  不x5
  T = 1.5  不x6  好x6  还x2  挺x4  凑x1  糟x1
```

T=0 二十次全是「好」；T=1.5 二十次里出了六种。

**这就解释了一件常见的事**：同一份提示词跑两次结果不一样——不是它不稳定，是你没把温度设为 0。

## 四、top_p：骰子只从"前几个"里挑

还有个旋钮常和温度一起出现：**top_p**。

它干的事更粗暴：

> 把候选按概率排队，累加到 top_p 就停，**后面的直接扔出牌桌**。

演示二的输出：

```
  top_p = 0.5   只剩 1 个候选：好
  top_p = 0.9   只剩 4 个候选：好、不、挺、还
  top_p = 1.0   只剩 6 个候选：好、不、挺、还、凑、糟
```

top_p=0.9 时，「凑」「糟」不是概率变低，是**连被抽的机会都没有**。

两者的分工，一句话分清：

| 旋钮          | 管什么                 |
| ----------- | ------------------- |
| temperature | 敢不敢选冷门的（改概率表的高低）    |
| top_p       | 冷门的还留不留在牌桌上（改候选的多少） |

**实际怎么用**：两个一起调会互相打架，所以惯例是**只调一个**——

- 要稳定、要能复现（写代码、抽数据、做评测）→ `temperature=0`
- 要文采、要发散（起名、写文案）→ `temperature 0.7~1.0`，或 `top_p=0.9`

## 五、它什么时候学会这些的：预训练 vs 推理

到这里有个更根本的问题：那张概率表是**谁写的**？

不是人写的。是模型自己从海量文本里统计出来的——这件事叫**预训练**。

打个比方，分清两个阶段：

|     | 预训练               | 推理          |
| --- | ----------------- | ----------- |
| 像什么 | 学生**刷题库**，刷了几万亿道  | 学生**上考场**答题 |
| 花多久 | 几个月，几千万美元         | 零点几秒        |
| 谁在干 | 大厂训练模型时           | 你每次调 API 时  |
| 结果  | 得到一堆**固定的数字**（权重） | 得到一句话       |

关键差别只有一句：

> **预训练会改变模型，推理不会。**

演示三就是在证明这件事——同一个输入连算 5 次：

```
    好  好  好  好  好
```

5 次全一样，而且**模型一个数字都没变**。它不是"记住了上次答的",是每次拿到同样的输入，把同一张表重算了一遍。

## 六、这两件事对你的实际影响

**1. 它不知道今天发生的事。**  
预训练有个截止日期，之后的事它一律不知道。你问它新闻，它不会说"我不知道"，它会从旧知识里编一个像样的——这就是昨天说的幻觉。

**2. 你纠正它，它不会真的改。**  
「以后回答都短一点」这句话只活在**这次对话的窗口里**。窗口一挤，或者开个新对话，它立刻恢复原样。因为它没在学习，只在读你这次递给它的纸。

**3. 所以"让它记住"只能靠外部**：把资料检索出来塞给它（后面学 RAG），或者把规矩写进每次都会发的系统提示词。指望它自己记住，一定失败。

---

## 七、今天两个新概念

1. **temperature（温度）** —— 调"抽签有多随性"的旋钮。`0` = 永远选概率最高的，每次一样；越大越发散。配套的 **top_p** 是同一组的第二个旋钮，管"牌桌上留几个候选"。**两个只调一个。**
2. **预训练 / 推理** —— 一对词。预训练是「刷题库」，几个月、改模型本身，学完就冻住；推理是「上考场」，每次调用现算一遍，**不改模型**。

> 今天不讲微调、不讲 logits 的公式、不讲 beam search。用到再说。

## 八、验收

一道题：

> 你写了个脚本，让模型把 200 条客户评论各打一个 1~5 分的标签，结果跑两遍，有 30 多条分数不一样。老板问你是不是模型不准。
>
> 按今天学的，问题在哪？怎么改？

**答：温度没设 0。**&#x6253;分这件事要的是「同一个输入永远给同一个输出」，但默认温度不是 0，模型每次都在**重新抽签**——同一条评论，这次抽到 4、下次抽到 5，所以两遍对不上。

改法：调用时把 `temperature` 设成 `0`。这时它不再抽签，永远取概率最高的那个候选，同一份输入跑一百遍结果都一样。

顺带一个判断标准：**只要你的任务能被机器核对（分类、打分、抽字段、生成 JSON），温度就该是 0；只有"想让它写得不一样"的任务才调高。**
