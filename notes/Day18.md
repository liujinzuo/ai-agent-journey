## 一、先讲个生活里的例子

你饿了，让室友带饭。

- 你说「随便带点吃的」——他带回来一碗汤面，你不吃辣，白等一顿。
- 你说「带一份盖饭，不要辣，装盒子别装袋」——你吃上了。

这两种说法的差别，不是室友听不听话，是**你有没有把要求说出来**。模型比室友还老实：你不说，它就按它见过的样子给你。

提示词的四件套，就是这四句话：

| 四件套 | 对应的那句话 | 管什么 |
|---|---|---|
| **角色** | 谁来做 | 用什么身份、什么口吻 |
| **任务** | 做什么 | 抽哪几个字段、答什么问题 |
| **约束** | 不许怎样 | 不许编、不许加解释、没有就填 null |
| **格式** | 交成什么样 | JSON / 表格 / 一句话 / 只能是哪几个值 |

## 二、实验：同一条消息，四版提示词

任务：从一条客服消息里抽出「订单号、问题类型、是否要求退款」。

消息是故意挑的，**里面根本没有订单号**，只说「好像是 SF 开头的一串」：

> 我上周买的那个杯子裂了，订单号好像是 SF 开头的一串，你们看着办吧，不给退我就去投诉。

四版是递进的：V1 什么都不说 → V2 说任务 → V3 加格式 → V4 再加约束和一条示例。温度全部设 0（回忆 Day15：这样每次结果才一样，比较才成立）。

### 实测结果

```
版本              直接解析      字段齐全      枚举合法      布尔值     order_id
------------------------------------------------------------------
V1 裸问           ✗         -         -         -       -
V2 只给任务         ✗         -         -         -       -
V3 加输出格式        ✓         ✓         ✓         ✓       null
V4 加约束 + 示例     ✓         ✓         ✓         ✗       null
```

V1 交的是一段散文（「这条消息其实不是客服发的，而是一位顾客发来的投诉……」），V2 交的是三条中文列表。两版都**没法用代码读**——`json.loads` 直接抛 `JSONDecodeError`。

V3 只说了一句「输出 JSON，schema 长这样」，出来的就是能直接解析的 JSON。

## 三、三个发现

**第一，格式是最硬的一条。**
V2 到 V3 之间，只加了「输出 JSON」和一段骨架，输出就从人话变成了机器能吃的结构。你以后写自动化，**第一步永远是先固定格式**，不是先琢磨措辞好不好听。

**第二，角色是最弱的一条。**
V3 的 system 里写着「你是客服工单助手」，V2 什么身份都没给——可 V2 照样给了像样的三条。角色有用，但它改变的是**口吻和视角**，不改变**交货形态**。指望写个「你是资深专家」就得到结构化输出，会失望。

**第三，约束是双刃剑（今天最值钱的一条）。**
看 V3 和 V4 的布尔值那一列：

- V3 判 `true`——「不给退我就去投诉」，这就是在要求退款。
- V4 判 `null`——因为它的规则里有「消息里没有明确写出的信息一律填 null」，模型认定「去投诉」不算明确写退款。

同一条消息，加了约束反而**漏抽了**。原因不是模型变笨，是我那条规则写得太死：**「没明确写出」和「能合理推断」是两件事，我没区分。**

所以约束不是越多越好。防编造的规则，写过头就变成漏抽的规则。这个平衡是 Day19 的主菜。

## 四、记住这几行就够

```python
system = (
    "你是客服工单助手。"                                  # 角色：谁来做
    "只输出一个 JSON 对象，不要 markdown 代码块，不要解释。"  # 格式 + 约束：交什么、不许加什么
    "三个字段必须都有：order_id 字符串、issue_type 枚举、refund_requested 布尔值。"
    "issue_type 只能是：物流 / 质量 / 退款 / 其他。"        # 枚举：把自由发挥关进笼子
    "消息里没有明确写出的信息一律填 null，绝对不要猜。"      # 约束：防编造
)
```

写提示词的顺序建议：**先定格式 → 再定枚举 → 再定缺失怎么办 → 最后才调口吻。**

反过来的顺序（先调口吻再想格式）是最常见的浪费：你把话说得很客气，结果输出还是不能自动用。

## 五、什么时候用

| 场景 | 要不要上四件套 |
|---|---|
| 自己聊天、问个概念 | 不用，正常说话就行 |
| 让代码读它的输出 | **必须**，格式和枚举一条都不能省 |
| 批量跑几百条数据 | **必须**，而且要先拿 5 条试跑，确认格式稳定 |
| 让它写文案、写周报 | 只要角色和任务，格式别卡太死，卡死了就干巴 |
