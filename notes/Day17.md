## 二、生活场景：办卡、刷卡、拿回执

- **注册开放平台** = 去物业办一张门禁卡
- **API key** = 卡号。有了它，门认识你，也认得出是你刷的
- **调用接口** = 刷卡进门，把「我要什么」递进去
- **回执** = 里面递出来的一张单子，写着它给了你什么、用掉多少

**卡号泄露等于卡丢了。** 别人拿你的卡刷，账单记在你头上。这也是为什么钥匙永远不进代码、不进 git、不截图。

4. 左侧找 **充值**，充最小额度。练习量很小，几块钱能跑几百次。
5. 回到仓库，把钥匙交给 `.env`：

```powershell

```

然后用记事本打开 `.env`，把 `sk-在这里填你自己的钥匙` 换成你复制的那串，**保存**（Ctrl+S）。

`.env` 已经在 `.gitignore` 里，不会被提交。我特意给 `.env.example` 开了例外（`!.env.example`），所以模板能进仓库，真钥匙进不去。

## 四、跑一遍

```powershell

```

如果 `.env` 没准备好，脚本不会崩，会直接把上面五步再打一遍。

跑通了，你会看到三段。

**第一段**是原始回执，一坨 JSON。下面是结构与字段的示例（**数字和内容是示例，你跑出来会不同**）：

```json
{
  "id": "9f2c...",
  "model": "deepseek-chat",
  "choices": [
    {
      "index": 0,
      "message": { "role": "assistant", "content": "token 是模型读写文字的最小单位。" },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 24,
    "completion_tokens": 18,
```

**第二、三段**是同一道打分题连跑两次，温度都是 0：

这就是 Day15 那道「200 条评论跑两遍分数不一样」的答案落地了：**默认温度不是 0，它每次都重新抽签；设成 0 才是每次取概率最高的那个。** 你之前没答那道题，今天用真接口验完了，算补上。

## 五、回执里只看三个字段

那坨 JSON 有十几个字段，**只有三个跟你有关**：

| 字段 | 是什么 | 你要拿它干什么 |
|---|---|---|
| `choices[0].message.content` | 模型说的话（字符串） | 你的程序真正要的东西 |
| `choices[0].finish_reason` | 它为什么停下 | **必须检查**，见下 |
| `usage` | 用掉多少 token | 算钱、算成本、判断是不是快超窗口 |

### finish_reason：它为什么停下

| 值 | 意思 | 危险程度 |
|---|---|---|
| `stop` | 正常说完了 | 正常 |
| `length` | 撞到 `max_tokens` 上限，**话没说完** | **危险** |
| `tool_calls` | 它要调工具（Day12 见过） | 正常，按工具调用流程走 |
| `content_filter` | 内容被安全策略拦了 | 少见，要兜底 |

`length` 为什么危险：你以为拿到了完整答案，其实是**半截**。如果它本该输出 JSON，你会拿到 `{"name": "张三", "age":` 这种残废字符串，然后 `json.loads` 直接报错——**错误出现在解析那一步，根因却在回执里**。

养一个习惯：**先看 `finish_reason`，再解析内容。** 这一行以后能救你无数次。

### usage：算钱用

```
prompt_tokens     你发过去的（提示词 + 历史）
completion_tokens 它生成的
total_tokens      两者之和
```

乘以官网当前单价就是这次的钱。单价会变，去价格页看，别记死数。但你要建立的直觉是：**同一个任务，提示词越长越贵，回答越长越贵**——Day14 的 token 直觉在这里第一次变现。

## 七、今天两个新概念

1. **API key** —— 你的门禁卡号。识别你是谁、算在谁账上。泄露 = 别人替你花钱。
2. **finish_reason** —— 回执里写明「我为什么停下」。`stop` 才算话说完了；`length` 代表被截断，**解析前必须先看它**。

## 八、验收

一道题：

> 你的脚本偶尔报 `json.decoder.JSONDecodeError`，把抓到的原始输出打出来一看，末尾是：
> `{"name": "张三", "age":`
>
> 回执里哪个字段能提前发现这件事？怎么改？

**答：`finish_reason == "length"`。**

模型不是"出错"了，是被 `max_tokens` 掐断了——它在正常情况下不会输出一句半截的 JSON，只有撞到长度上限才会。所以半截 JSON 的根因不在解析，在长度。

三种改法，按代价从小到大：

1. **调大 `max_tokens`**：先看这个任务到底需要多长，给足余量。
2. **提示词里限长**：例如「只输出 JSON，不要解释」，把废话挤掉。
3. **代码里先判后解**：拿到回执先看 `finish_reason`，是 `length` 就重试或报明确错误，别让 `json.loads` 抛一个看不出原因的解码错。

一句话记住：**先问"它说完了吗"，再问"它说了什么"。**
