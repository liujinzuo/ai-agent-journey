# Day13 · 发请求

> 一句话：**你的程序"问"模型，其实是寄一个包裹 —— 地址 + 钥匙 + 内容，换回一张回执。**

---

## 一、为什么今天要学这个

前十二天里，所有"模型的回答"都是我提前写死在脚本里的。

Day12 那个 `day12_tool_call.py` 里，模型说"我要调 get_weather"，那句话是我打的字，不是模型说的。

从今天起要换成真的。而真模型不在你电脑里，它在别人的服务器上——**你唯一能和它打交道的方式，就是发一个 HTTP 请求过去。**

所以今天不讲新语法，讲**怎么把一句话送到另一台机器上，再把回答拿回来**。

---

## 二、生活里的场景：寄快递

你给外地的朋友寄东西，要做三件事：

| 寄快递 | 请求模型 |
|---|---|
| 写清收件地址 | **URL**：`https://api.xxx.com/v1/chat` |
| 出示身份证 / 门禁卡 | **API key**：那串 `sk-` 开头的字符 |
| 把东西装进箱子 | **请求内容**：一段 JSON（你的提问 + 工具清单） |

对方收到后，给你一张**回执**：签收了（200），或者拒收（401 没带证件）。

**就这三样东西，没有第四样。** 所有模型 API 的形状都是这个，DeepSeek、Kimi、通义、OpenAI，只是地址和内容格式略有差别。

```powershell
cd C:\Users\22155\ai-agent-journey

```

这个脚本**不需要联网、不需要 API key**。它在你自己电脑上起了一个假的"模型服务器"，然后用真实的方式向它发请求。

第一次，**不带钥匙**：

```
寄出的包裹：
  地址： http://127.0.0.1:54588/v1/chat
  方法： POST
  钥匙： (没带)
  内容： {"model": "fake-model", "messages": [{"role": "user", "content": "北京未来三天天气怎么样？"}]}
  [服务器] 收到请求： /v1/chat
  [服务器] 看到钥匙： (空的)
收到回执：状态码 401
回执内容： {"error": "钥匙不对或没带钥匙"}
```

第二次，**带上钥匙**：

```
  钥匙： Bearer sk-test-123
  [服务器] 看到钥匙： Bearer sk-test-123
收到回执：状态码 200
回执内容： {"role": "assistant", "content": "", "tool_calls": [{"name": "get_weather", "arguments": {"city": "北京", "days": 3}}]}
```

注意最后那段——**这就是 Day12 说的那张单子**。现在它是真的从"服务器"那头传回来的，不再是我写死的字符串。

而且把整条线串起来了：你寄过去的问题 → 模型回一张单子 → 你的代码去执行 → 再寄一次把结果告诉它。

## 四、状态码：对方的三种表情

| 码 | 意思 | 你该干什么 |
|---|---|---|
| **200** | 收到了，给你 | 解析内容 |
| **401** | 你是谁？钥匙不对或没带 | 检查 key |
| **429** | 你问得太快了 | 等一会儿再试 |
| **500** | 对面自己出问题了 | 重试，不是你的错 |

记住一个判断法：**4 开头的错在你，5 开头的错在对方。**

新手最容易把 401 当成"代码写错了"，然后改半天代码。其实只是钥匙没带对。

---

## 五、钥匙的三条铁律

这串 `sk-xxxx` 就是你的钱包。谁拿到，谁就能用你的账号花钱。三条：

1. **不写死在代码里。** 写进去，一 commit、一 push，全世界上网的人都能搜到。GitHub 上有机器人专门扫这个，几小时内就会有人拿去刷。
2. **不截图分享。** 发群、发帖、问问题时，把 key 那几位糊掉。
3. **不进 git。** 放在一个叫 `.env` 的文件里，并把这个文件名写进 `.gitignore`，它就永远不会被提交。

正确做法是代码里这样写：

```python
import os
api_key = os.environ.get("MY_API_KEY")   # 从环境变量读，代码里看不到真实值
```

然后在 PowerShell 里临时给它：

```powershell
$env:MY_API_KEY = "sk-你的真实key"
```

**代码和钥匙分开放**，代码可以随便分享，钥匙只在你机器上。

## 六、真模型的地址长什么样

等你拿到 key，把今天的脚本换成真地址就行，形状完全一样：

| | 今天演示的 | 真实模型 |
|---|---|---|
| 地址 | `http://127.0.0.1:54588/v1/chat` | `https://api.deepseek.com/chat/completions` |
| 方法 | POST | POST |
| 钥匙 | `Bearer sk-test-123` | `Bearer sk-你的key` |
| 内容 | `{"model":..., "messages":[...]}` | `{"model":"deepseek-chat", "messages":[...]}` |

**变的只有地址和内容的具体字段，寄包裹的动作一模一样。**

## 七、今天两个新名词

1. **HTTP 请求** —— 就是上面那个"包裹"：地址 + 方法 + 头部（含钥匙）+ 内容。
2. **API key** —— 证明"是你"的凭证，通常放在请求头的 `Authorization` 里，格式是 `Bearer sk-xxxx`。

> 提醒：今天不讲 `GET / POST` 的区别、不讲 `REST`、不讲 `https` 加密。这些以后遇到再说，现在只记住"寄包裹"这一件事。

## 八、验收

一道题：

> 你写了个脚本调模型，跑起来报 **401**。你把代码从头到尾检查了三遍，语法没问题。
>
> 最可能是哪里错了？

**答：钥匙那串字符串跟服务器记的不完全一样。** 最常见就是多了一个空格（或多一个换行）。

为什么一个空格就能挡住你：服务器比的是**精确字符串**，`"Bearer sk-123 "` 和 `"Bearer sk-123"` 在它眼里是两个不同的东西，前者不认识，于是回 401。而它通常只告诉你「invalid api key」，**不会告诉你是多了个空格**——所以你会去怀疑代码，其实代码完全正确。

三个同源的坑，遇到 401 依次排查：

1. **复制时带了空格或换行**：从网页复制 key，末尾常带一个看不见的换行符。处理办法是 `.strip()`。
2. **前缀漏了**：必须是 `Bearer ` + 空格 + key。只写 key 不加 `Bearer`，同样 401。
3. **key 被截断或已失效**：少了中间几位、或者你在平台点了「删除/重置」。去控制台重新复制一次最省事。

一句话记住：**401 永远先怀疑钥匙，不要先怀疑代码。**
