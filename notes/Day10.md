# Day10 · 异步：等待的时候别干站着

> 配套脚本：`code/day10_serial.py`（笨办法）、`code/day10_concurrent.py`（聪明办法）
> 今天只回答一个问题：**同样三件事，为什么一份要 3 秒、一份只要 1 秒。**

---

## 零、生活里的场景

你要烧三壶水，泡三杯茶。

**笨办法**：点第一壶 → 站在旁边盯着它开 → 开了倒水 → 再点第二壶 → 再盯着它开……

**聪明办法**：三壶一起点上 → 一起等 → 谁先开先倒谁。

差别在哪？差别在：**水在烧的时候，你是闲着的。**

人只有一双手，但「等」这件事不需要用手。笨办法把「等」当成了「干活」，白白站了 3 分钟。

一句话记住今天：

> **等待的时间不是你干活的时间，浪费它就是在浪费你的程序。**

## 一、先看笨办法（第一段）

```powershell
cd C:\Users\22155\ai-agent-journey
.venv\Scripts\python.exe -X utf8 code\day10_serial.py
```

输出：

```
第一壶：开始烧水
第一壶：茶好了
第二壶：开始烧水
第二壶：茶好了
第三壶：开始烧水
第三壶：茶好了
总共用了 3.0 秒
```

看那个**顺序**：开始、好了、开始、好了……永远是「一壶做完才轮到下一壶」。

这就是**串行**：一件一件排队做。

---

## 二、再看聪明办法（第二段）

```powershell
.venv\Scripts\python.exe -X utf8 code\day10_concurrent.py
```

输出：

```
第一壶：开始烧水
第二壶：开始烧水
第三壶：开始烧水
第一壶：茶好了
第二壶：茶好了
第三壶：茶好了
总共用了 1.0 秒
```

**顺序变了。** 三个「开始」挤在一起，三个「好了」挤在一起。

这就是**并发**：三件事同时在等，谁先等到谁先说。

**耗时从 3.0 秒变成 1.0 秒，代码干的活一模一样。**

## 三、代码只改了三个地方

对比两份脚本，区别就三处：

| 笨办法 | 聪明办法 | 这处在干什么 |
|---|---|---|
| `def make_tea(...)` | `async def make_tea(...)` | 加 `async`：告诉 Python「这个函数里会等」 |
| `time.sleep(1)` | `await asyncio.sleep(1)` | `await`：**我在这等，你先让别人干** |
| 依次调用三行 | `await asyncio.gather(三个一起)` | `gather`：三件事一起派出去 |

最要紧的是第二行。

`time.sleep(1)` 和 `asyncio.sleep(1)` 都是「等 1 秒」，但性质完全不同：

- `time.sleep(1)` —— 堵住。整个程序停在这，谁也不许动。
- `await asyncio.sleep(1)` —— 让出去。**「我要等 1 秒，这 1 秒你去干别的」**，1 秒后回来接着干。

`await` 这个词念「额威特」，你可以直接记成**「等我一下，你先忙」**。

---

## 四、为什么 Agent 特别吃这一套

Agent 干的活，绝大部分时间都在**等别人**：

- 等模型返回一段话（2~10 秒）
- 等网页抓完（1~5 秒）
- 等数据库查完（几十毫秒到几秒）

这期间你的电脑几乎什么都没干，纯坐着等。串行做 5 次网络请求，就是 5 个「等」相加；并发做，只等于最慢的那一个。

再往下想一步：真实 Agent 经常要**同时问几个工具**——查天气、查日程、查路况，三个结果凑一起才能回答。这三件事互不依赖，天然就该并发。

**所以「会并发」不是加分项，是 Agent 的基本功。**

## 五、今天只需要记两个名字

1. **`async def` / `await`** —— 给函数贴个标签「我会在里面等」，再在等的地方写 `await` 把时间让出去。两个词是一套，一起记。
2. **`asyncio.gather`** —— 把几件事**一起派出去**，等它们全部回来。念「盖则」。

另外那行 `asyncio.run(main())` 你当它是**开关**：整个异步程序只有最外面这一句是这形状，照抄就行，不用理解。

写法模板（背这个形状就够）：

```python
async def 一件事(参数):
    print("开始")
    await asyncio.sleep(1)     # 要等的地方都写 await
    print("好了")

async def main():
    await asyncio.gather(一件事("A"), 一件事("B"), 一件事("C"))

asyncio.run(main())
```

## 六、一句实话，别记错

**并发不会让单件事变快。**

一壶水该烧 1 分钟还是 1 分钟。并发省下的是**「你在旁边干站着」的那段时间**。

所以判断标准很简单：**几件事之间互相不依赖（谁先谁后都行），就该并发；后一件必须用前一件的结果，就只能串行。**

## 八、验收

一道题：

> 你要做两件事：① 先从数据库查出用户的订单号；② 再拿这个订单号去查物流。
>
> 这两件事**应该**用 `asyncio.gather` 一起做吗？

答：**不能。** 第二件事必须用第一件事的结果（订单号），没有订单号根本没法查物流——**后一件依赖前一件，只能串行。**

`gather` 只适合「互不相干、谁先谁后都行」的几件事。一旦有依赖，顺序就是硬要求，快不了。
