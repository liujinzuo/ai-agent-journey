## 零、今天解决什么问题

前面十一天你写的东西，全是「自己干」：算数、存文件、判断、循环、并发。

Agent 不一样。**Agent 的关键动作是「让模型决定干什么，让你的代码去干」。**

今天只搞清楚这一件事：**模型到底是怎么「调用」你的代码的？**

答案是——它根本没有调用。它只是**说了一句话**。

---

## 一、点菜：顾客不下厨

你是服务员，顾客是模型，厨房是你的代码。

顾客不会冲进厨房炒菜。他只会说：

> 「一份宫保鸡丁，不要花生。」

这句话里有两样东西：**菜名**（宫保鸡丁）+ **要求**（不要花生）。

接下来是**你**拿着单子进厨房，告诉厨师怎么做，做好了端回去。

Function Calling 就是这件事的标准化：

| 饭馆 | Agent |
|---|---|
| 菜单（有哪些菜） | **工具清单**：你能提供哪些函数 |
| 顾客说「宫保鸡丁，不要花生」 | 模型说「用 get_weather，city=北京，days=3」 |
| 服务员进厨房下单 | 你的代码真的调用函数 |
| 端菜回去 | 把函数结果塞回给模型 |
| 顾客吃/评价 | 模型看着结果回答用户 |

**一句话记死：模型只点菜，它一口锅都碰不到。**

## 二、跑一遍，看五步

```powershell
cd C:\Users\22155\ai-agent-journey
.venv\Scripts\python.exe -X utf8 code\day12_tool_call.py
```

输出分五段，一段对应一步：

**第 1 步：递菜单**
```
{"name": "get_weather", "description": "查某个城市未来几天的天气",
 "parameters": {"city": "城市名", "days": "天数，整数，默认 1"}}
```

你必须**先告诉模型**你有哪些工具、每个工具干什么、要什么参数。它才知道自己「能点什么菜」。不递交菜单，它就只会跟你聊天。

**第 2 步：模型点菜**
```
{"name": "get_weather", "arguments": {"city": "北京", "days": 3}}
```

注意：**它没有回答「北京天气怎么样」**，它只给了一个「调用请求」——哪个工具、参数填什么。

这就是 Day8 你定义过的 `ToolCall(name, arguments)`。

**第 3 步：验菜**
```
参数检查通过： city='北京' days=3
```
Day9 的检查关口在这里。模型给的参数是它猜的，先验再下厨。

**第 4 步：下厨**
```
工具返回： 北京 未来 3 天都是晴，18~25 度
```
这一步**是你的代码在跑**，跟模型没有任何关系。你的函数该多慢还多慢。

**第 5 步：端回去**
```
（下一轮发给模型的内容：工具 get_weather 返回了「北京 未来 3 天都是晴…」）
```

把结果塞回对话，**再问模型一次**。模型看到「哦，查到了晴天」，才用自然语言回答用户。

**所以一次工具调用，实际上是「问了模型两次」。** 这一点第一次接触的人几乎都会漏掉。

## 三、必须拧过来的一个想法

新手最容易以为：模型能看见我的代码、能跑我的函数。

**它看不见。** 它只知道你递给它的那张菜单。

推论有三条，全部很实用：

1. **你的函数做了什么，模型完全不知道**——它只看到你递回去的结果字符串。
2. **菜单写得糙，模型就点错菜**——`description` 写得含糊，它会在该用 A 工具时用了 B。这是最常见的 Agent 故障，且**绝大部分是提示词问题，不是模型笨**。
3. **菜单上没有的，它点了也没用**——你的程序里没有对应函数，只能报错或忽略。

---

## 四、今天两个新名词

1. **工具清单（tools）** —— 递给模型的「菜单」：每个工具的名字、干什么用、要什么参数。
2. **工具调用（tool call / function calling）** —— 模型返回的那个「点菜单」：要调哪个工具 + 参数填什么。

---

## 五、一句话总结

> **模型不执行任何东西，它只输出「用哪个工具、参数填什么」；真正干活的是你的代码，干完把结果端回去，它才会开口回答。**

## 七、验收

一道题：

> 你的菜单上只有 `get_weather` 一个工具。模型却返回了
> `{"name": "get_stock", "arguments": {"code": "600519"}}`。
>
> 接下来会发生什么？

- **A.** 模型自己上网查股价，把结果给你
- **B.** 你的程序在菜单里找不到 `get_stock`，只能报错或干脆忽略
- **C.** 平台会自动补一个查股价的功能

答：**B。** 你的程序在菜单里找不到 `get_stock`，只能报错或干脆忽略——模型点了它也没用，因为**能执行的只有你代码里真有的函数**。

真实 Agent 里不一定会「忽略」，更常见的处理是：**把「没有这个工具」本身当成一条结果回给模型**

```
{"error": "没有名为 get_stock 的工具，可用的只有：get_weather"}
```

模型看到这句，通常会换个办法（改用别的工具，或者直接告诉用户「我查不到股价」）。

**这条思路要记住：错误也是一种结果，回给模型，让它自己调整。** 这就是 Day4 说的「异常是给程序看的，错误信息才是给模型看的」在 Agent 里的落地。
