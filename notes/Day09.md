## 一、先说一个生活里的场景

你去办事，窗口给你一张表：

```
姓名：__________（必填）
年龄：__________（填数字）
```

这张表上印着要求。但**纸不会自己看**。

你把年龄那栏写成「随便」，纸照样收下，安安静静。等你把表交上去、别人拿去做统计的时候，才发现这栏根本不能用——而你早就走了。

**昨天学的类型注解，就是印在纸上的那行字。** Python 不看它。这一点昨天已经验证过了。

那怎么办？**在收表的地方站一个人，当场看一眼。** 这个人就是今天的主角。

脚本里就一处不对：天数那栏填的是 `"三天"`，不是数字。

```python
a = WeatherArgs(city="北京", days="三天")
print(a.days * 24)
```

你看到的输出是这样：

```
城市： 北京
天数： 三天
现在拿它算小时数（days * 24）：
三天三天三天三天三天三天三天三天三天三天三天三天三天三天三天三天三天三天三天三天三天三天三天三天
```

**没有报错。** 它把「三天」这个字符串重复了 24 遍。

因为对 Python 来说，`"三天" * 24` 的意思是「把这个字符串复制 24 份」，完全合法。

这就是没有检查员的后果：**它不吵不闹，给你一个荒唐的结果，然后继续往下跑。** 你要等到几百行之后，看到一屏「三天三天三天」，才知道出了问题——而这时已经不知道是哪一步填错的了。

## 三、请个检查员站那儿（第二段）

跑这个：

```powershell
.venv\Scripts\python.exe -X utf8 code\day09_pydantic.py
```

代码和第一段几乎一样，只改了两个字：

```python
from pydantic import BaseModel

class WeatherArgs(BaseModel):     # 原来是 class WeatherArgs:
    city: str
    days: int
```

注意：**`__init__` 不用写了。** 昨天你自己动手把参数一个个存进 `self`，今天不用了，交给它。

跑出来的结果：

```
===== 第一次：故意填错（days 给了「三天」）=====
被拦下来了，报错原文：
1 validation error for WeatherArgs
days
  Input should be a valid integer, unable to parse string as an integer [type=int_parsing, input_value='三天', input_type=str]
...

===== 第二次：填对（days 给 3）=====
通过了： city='北京' days=3
算小时数： 72
```

报错原文翻成人话，就三句：

| 原文 | 人话 |
|---|---|
| `1 validation error for WeatherArgs` | 这张表有 1 栏填错了 |
| `days` | 错的是「天数」那一栏 |
| `Input should be a valid integer` | 这栏得是整数，你给的不是 |

**它不但拦住了，还告诉你是谁、错在哪、该填什么。** 这就是检查员和一张纸的区别。

## 四、为什么 AI Agent 特别需要这个人

AI 模型不会直接帮你干活，它是**告诉你「我想调用哪个工具、参数填什么」**，由你的程序去执行。

而那些参数是模型「猜」出来的，用的是 JSON 文本。它可能：

- 少填一栏
- 把数字填成字符串（就像今天的「三天」）
- 多塞一栏你没定义的

如果不管，你的程序就会拿着荒唐的参数去执行——查天气的接口收到「三天」，要么报一个你看不懂的错，要么返回一个荒唐的结果。

所以真实 Agent 里都有这么一道关口：

```
模型说「我要用 get_weather，参数是这些」
        ↓
  WeatherArgs 这道关口检查
        ↓
   通过 → 真的去执行
   不通过 → 把那段报错原样回给模型：「你填错了，days 要整数」
           模型看到后自己改，再交一次
```

第二种情况叫「让模型自我修正」，它是 Agent 能稳定干活的关键之一。而它成立的前提，就是**你得能明确地告诉模型「哪里错了」**——这正是 Pydantic 免费给你的东西。

## 五、今天的两个新名词（记住这两句就够）

1. **Pydantic** —— 一个专门做检查的库。用一句话说：**它站在收表的地方，帮你把填错的表退回去。**
2. **BaseModel** —— 你写的那个模板要继承的东西。括号里写上它，这个类就从「一张纸」变成「有人守着的窗口」。

写法上只要记住这个形状：

```python
class 表名(BaseModel):
    栏位名: 类型
    栏位名: 类型 = 默认值
```

## 八、验收

一道题，答对了：

> 模型返回 `days="3"`（带引号的 3），Pydantic 会怎么办？
> **答：B —— 放过去，自动把 `"3"` 变成 `3`。**

理由：`"3"` 它看得懂是什么意思，就顺手帮你转了；只有看不懂的（`"三天"`）才拦。
所以它**不是死板地查类型，而是先尽力理解，理解不了才拒绝**——这一点记住，以后跟模型打交道时会反复遇到。
